4. rexbox 브랜치 `i062-title-thread`: `9e2fa23`(#62), `b61f4ea`(#63), `a0744fb`(#64).

# Work log: the stop after START at the title (issue #7)

Design: [20261105-i007](../design/20261105-i007-start-stall.md) · Work order: [20261105-i007](../work-orders/20261105-i007-start-stall.md)

Done:
1. Reproduction. `SendKeys` press and release were handled in one pump and START never registered. Holding Enter for 0.25 s through `keybd_event` reproduces the stop: the same shape as the user's log, last present 4361–4406. A hidden window (`REXBOX_DISPLAY=hidden`) does not reproduce it.
2. A direct-call profile build (`build/win32_x86_prof`, `REXBOX_RECOMP_CALL_PROFILE=ON`). Thread 3's last call was `sub_00076360` → `D3DDevice_Swap_0__LTCG_eax1` (a tail jump), so it was inside the HLE Swap, not in game code.
3. Host stacks, from a dbghelp `StackWalk64` tool with names from the MAP file:
   * first `SetWindowTextW` → `NtUserMessageCall` (rexbox #62);
   * after that fix, a critical section that did not hand off (rexbox #63);
   * after that, six snapshots all showing `glGetError <- GetVideoMemoryInfo <- SettingsUi::Record` (rexbox #64).
4. On rexbox branch `i062-title-thread`: `9e2fa23` (#62), `b61f4ea` (#63) and `a0744fb` (#64).

Submodule: `third_party/rexbox` is at rexbox `v0.0.23` (`25587f7`, the squash merge of reexec/rexbox#66); on the branch the commits were #62 `9e2fa23`, #63 `b61f4ea` and #64 `a0744fb`.

Verification:
- Win32 x86 Debug and Release: 0 errors and 0 warnings, CTest 7/7 in both.
- `reexceed roms` (window shown, audio, keyboard): START at the title → SELECT MODE → the ARCADE song select (BANYA CHANNEL) → difficulty select, with no stop in 120 s.

Remaining: the loading-screen thread's GL work has no effect (rexbox [#65](https://github.com/reexec/rexbox/issues/65)).
