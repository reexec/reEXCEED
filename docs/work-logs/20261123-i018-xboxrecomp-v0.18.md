## 경과

1. 원격과 동기화: 로컬 `main`이 이미 `origin/main`(v0.0.9, `5c1d8bc`)과 같았다. upstream xboxrecomp에 v0.17.0(`343b6d8`), v0.18.0(`37b61d5`)이 새로 있었다.
2. 시험 lift(v0.18.0, 임시 패치 없이): 함수 5,547개, 실패 0, 미해결 호출 대상 3 → 0, 미구현 명령 74 → 10, 생성 C 약 104만 → 114만 줄(+9.4%), lift 단계 61 → 약 42초. Release 빌드는 경고·오류 없음.
3. `reexceed_decomp_check`에서 `sub_00038D60`이 달라졌다(`ebp` 66666666 대 55555555, `g_seh_ebp`, 스택 `0x00EFFEE0`). 새 lift 코드는 호출 직전과 `ret`에서 `g_ebp`·`g_seh_ebp`를 쓰고(upstream #280), 호출자가 CF를 읽어 `ret`에서 `g_eflags`를 쓴다(#311). 디컴파일 코드에 같은 게시를 넣자 일치했다.
4. 생성 코드에서 libpng `png_handle_IHDR`의 `imul bl`이 `SET_LO16(eax, …)`만 쓰는 것을 확인하고(upstream #277), 사용자 결정에 따라 #6 수정만 지우고 패치 메커니즘은 남겼다.
5. 검사 도구는 `g_eflags`를 비교하지 않았다. 비교를 더하고, `sub_00038D60`의 플래그를 일부러 `0x45`로 바꾸자 `g_eflags decompiled 00000657 lifted 00000656`으로 잡히는 것을 확인한 뒤 되돌렸다.
6. `/wd4310`을 빼고 빌드하자 C4310 5건(`reexceed_game` 4, `reexceed_decomp_check` 1)이 나와 유지했다.

# Work Log: Moving to xboxrecomp upstream v0.18.0 (issue #18)

* Related issue: #18
* Design: [`docs/design/20261123-i018-xboxrecomp-v0.18.md`](../design/20261123-i018-xboxrecomp-v0.18.md)
* Work order: [`docs/work-orders/20261123-i018-xboxrecomp-v0.18.md`](../work-orders/20261123-i018-xboxrecomp-v0.18.md)

## Progress

1. Sync with the remote: local `main` already equalled `origin/main` (v0.0.9, `5c1d8bc`). Upstream xboxrecomp had new releases v0.17.0 (`343b6d8`) and v0.18.0 (`37b61d5`).
2. A trial lift (v0.18.0, without the temporary patch): 5,547 functions, no failures, unresolved call targets 3 → 0, unimplemented instructions 74 → 10, generated C about 1.04 → 1.14 million lines (+9.4%), the lift step 61 → about 42 s. The Release build had no warnings or errors.
3. `reexceed_decomp_check` showed `sub_00038D60` differing (`ebp` 66666666 against 55555555, `g_seh_ebp`, the stack at `0x00EFFEE0`). The new lifted code writes `g_ebp` and `g_seh_ebp` right before calls and at `ret` (upstream #280), and `g_eflags` at `ret` because callers read CF (#311). With the same writes in the decompiled code the case matched.
4. In the generated code libpng's `imul bl` in `png_handle_IHDR` writes only `SET_LO16(eax, …)` (upstream #277), so, as the user decided, only #6's fix was removed and the patch mechanism stays.
5. The check tool did not compare `g_eflags`. The comparison was added; breaking `sub_00038D60`'s flags to `0x45` on purpose was caught as `g_eflags decompiled 00000657 lifted 00000656`, then reverted.
6. A build without `/wd4310` gave five C4310 warnings (four in `reexceed_game`, one in `reexceed_decomp_check`), so it stays.
