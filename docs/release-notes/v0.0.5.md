## reEXCEED v0.0.5 (English)

The changes since **v0.0.4** (part of issue #9). **Guest memory no longer runs out as songs are played, so the in-game background (BGA) movie and the STAGE BREAK and GAME OVER videos show.**

Issue: #9 (in progress), guest memory running out: `D3D_DestroyResource` bound in the profile, rexbox #67–#69 (`8a8a2af`).

Changes: the profile's XDK internals gain `D3D_DestroyResource` = `0x00177E60`, so the library body frees the textures the title made when it drops them.

Submodules:
- `third_party/rexbox` at rexbox `v0.0.24` (`eec649c`, was `v0.0.23`).
- `third_party/xboxrecomp` unchanged at upstream `v0.16.0` (`f0f8a46`).

Known limits:
- Locked songs' pictures and the centre preview do not show on the song select (#9).
- The music sometimes does not play (#9).
- The loading-screen thread's GL work has no effect (rexbox #65).

Verified:
- Win32 x86 Debug and Release (generated code): 0 errors and 0 warnings, CTest 7/7.
- `reexceed roms` (window shown, audio, keyboard): song select → gameplay (BGA) → GAME OVER → save → SELECT MODE, with no exhaustion and no stop in 181 s. The user's check confirms that the BGA, STAGE BREAK and GAME OVER are fixed.

The source archives do not contain the submodules. To build, clone with `git clone --recurse-submodules https://github.com/reexec/reEXCEED.git`.
