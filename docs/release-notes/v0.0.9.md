### 알려진 한계

* X11(GLX)에서는 x64·x86 모두 첫 그림 직후 게임 메인 스레드가 반환하고, GL 컨텍스트가 없는 게스트 스레드의 그리기가 드라이버 안에서 fault한다([rexbox #85](https://github.com/reexec/rexbox/issues/85)). Wayland 세션에서 실행한다.
* x86은 NVIDIA 드라이버의 Wayland에서 EGL 창 서피스를 만들지 못해 화면이 없다. 그 실행은 SIGTERM으로 끝나지 않았다([rexbox #86](https://github.com/reexec/rexbox/issues/86)).
* 로딩 화면 스레드의 GL 작업은 효과가 없다(rexbox #65).

## reEXCEED v0.0.9 (English)

The changes since **v0.0.8**. **The recompiled code is generated and x64 and x86 are built on a Linux machine, and x64 runs on Wayland.**

* [#16](https://github.com/reexec/reEXCEED/issues/16) (`b7925a8`): on a Linux machine (Ubuntu 26.04.1, GCC 15.2, CMake 4.2.3), `regenerate.py` lifts 5,547 functions with no failures (as on Win32), the x64 and x86 Release builds succeed, and x64 runs on Wayland. `scripts/build_linux.sh` is stored as executable (100755). The Linux guide gains the machine results and its known limitations (section 8).

Submodules unchanged: `third_party/rexbox` at rexbox `v0.0.26` (`f4878af`), `third_party/xboxrecomp` at upstream `v0.16.0` (`f0f8a46`).

Known limits: on X11 (GLX), x64 and x86 alike, the title's main thread returns right after the first picture and a guest thread without the GL context faults inside the driver when it draws ([rexbox #85](https://github.com/reexec/rexbox/issues/85)); run in a Wayland session. On NVIDIA's Wayland the x86 build cannot create its EGL window surface, so there is no picture, and that run did not end on SIGTERM ([rexbox #86](https://github.com/reexec/rexbox/issues/86)). The loading-screen thread's GL work has no effect (rexbox #65).

Verified: Linux x64 Release (generated code, GCC 15.2) and x86 Release (-m32) with 0 errors and 0 warnings and CTest 7/7; x64 hidden run through boot, title and attract at 60 fps with no stop (NVIDIA RTX 4090, Wayland), and the windowed run checked by the user.

The source archives do not contain the submodules. To build, clone with `git clone --recurse-submodules https://github.com/reexec/reEXCEED.git`.
